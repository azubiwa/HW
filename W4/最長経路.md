# 問題

"渋谷"から"池袋"まで、Wikipediaのリンクをパスとしたときに、重複した単語を通らない最長パスを求める

# 解法

## 基本的なアイデア

基本的にDFSを用いて、経路を求める。

- seenには、xのリンク先を確認するタイミングでxを入れる
- 事前にidごとにリンク先を ~~出次数~~ page rankでsortしておく
- 同じ単語からは、~~リンク先が少ない/多い~~ page rankが低いものを優先して確認する
- 探索する時間を決めることで、一旦ゴールが出てもまだ探索するようにする
- 途中でゴールまでの経路を見つけた時は、一度100個前までのどこかにランダムに遡って経路を探し直す（バックトラック）

## 主な変数

| 変数名            | 型   | 概要                                                      |
| ----------------- | ---- | --------------------------------------------------------- |
| seen              | set  | 探索をした頂点                                            |
| sorted_links_list | dict | linksの各idごとに出次数の昇順で並べたもの                 |
| stack             | list | dfsで次に見る経路                                         |
| max_len           | int  | それまでの最長の経路長                                    |
| best_path_ids     | list | max_lenに対応する経路                                     |
| max_backtrack     | int  | ゴールまでの経路を見つけた後、やり直す最大数              |
| backtrack_steps   | int  | max_backtrackまでのランダムな数で、今回やり直すステップ数 |
